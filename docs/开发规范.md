## 5. 用户业务模块开发

参考 `jffast-biz/jffast-demo` 模板（`DemoExample`）：

1. 在 `jffast-biz/` 下创建 `jffast-{业务名}` 目录

6. 在 `jffast-bom` 中添加版本管理条目

完整 CRUD 示例（见 §7、§8、§9）。

## 6. 命名规范总则

- 类名：大驼峰；方法/字段：小驼峰；常量：全大写下划线
- 布尔字段/方法：以 `is/has/can` 开头（Entity 基类字段除外）
- 表名：`snake_case` 复数语义；字段名禁止使用数据库保留字
- Controller 后缀 `Controller`，Service 后缀 `Service`，Mapper 后缀 `Mapper`，Entity 用业务名（如 `Order`）
- 包内分层用目录表达，不重复业务名（如 `entity/Order`，不要 `entity/OrderEntity`）

## 7. Entity 规范

- 必须继承 `BaseEntity`，不要重复定义 `id`/`tenantId`/`deptId`/`createBy`/`createTime`/`updateBy`/`updateTime`
- 使用 `@TableName` 指定表名，`@Schema(description)` 添加字段描述
- ID 自动生成：`BaseEntity` 已配置 `@TableId(type = IdType.ASSIGN_ID)`
- 逻辑删除**默认不启用**：Base 未开启 `@TableLogic`，删除是物理删除，表里也不建 `is_deleted` 列。需要逻辑删除的表自行加 `is_deleted` 列 + `@TableLogic`，**两者必须同时到位**（只加列 = 死列，只加注解 = 运行期 `Unknown column`）

```java
@Data
@EqualsAndHashCode(callSuper = true)
@TableName("biz_order")
@Schema(description = "订单实体")
public class Order extends BaseEntity {
    @TableField("order_no")
    @Schema(description = "订单号")
    private String orderNo;

    @Schema(description = "金额")
    private BigDecimal amount;
}
```

## 8. Service 规范

- 继承 `BaseService<Mapper, Entity>`
- 禁止手动设置 `createBy`/`createTime`/`updateBy`/`updateTime`（由自动填充处理）
- 分页查询用 `LambdaQueryWrapper` + `PageUtil.resultPageMp(page)`
- 事务边界：单表默认不加；跨表强一致必须加 `@Transactional(rollbackFor = Exception.class)`，避免长事务（见 §15）

```java
@Service
public class OrderService extends BaseService<OrderMapper, Order> {
    public PageRes<Order> page(Integer pageNo, Integer pageSize, String orderNo) {
        LambdaQueryWrapper<Order> query = new LambdaQueryWrapper<>();
        query.like(StrUtil.isNotBlank(orderNo), Order::getOrderNo, orderNo);
        query.orderByDesc(Order::getCreateTime);
        Page<Order> page = this.page(new Page<>(pageNo, pageSize), query);
        return PageUtil.resultPageMp(page);
    }
}
```

## 9. Controller 规范

- 继承 `BaseController<Service, Entity>`
- 写操作必须加 `@SLog(title = "xxx")`
- 新增接口加 `@RateLimit(value = "default")`
- 新增/保存类接口加 `@Idempotent(expire = 5)` 防重复提交（见 §17）
- 修改接口加 `@DistributedLock(key = "'module:' + #params.id", expireTime = 10000)`
- 统一通过 `R` 封装返回，不直接返回裸对象
- 入参/DTO 校验用 `@Valid`（见 §12）

```java
@RestController
@RequestMapping("/demo/example")
@Tag(name = "示例管理")
public class DemoExampleController extends BaseController<DemoExampleService, DemoExample> {

    @GetMapping("/page")
    @SaCheckPermission(orRole = BaseConstant.ROLE_SUPER_ADMIN, value = "demo:example:view")
    @Operation(summary = "分页查询")
    public R page(DemoExampleQueryRequest query) {
        return R.success(service.page(query));
    }

    @SLog(title = "新增示例")
    @PostMapping("/create")
    @RateLimit(value = "default")
    @SaCheckPermission(orRole = BaseConstant.ROLE_SUPER_ADMIN, value = "demo:example:add")
    @Operation(summary = "新增")
    public R create(@RequestBody @Valid DemoExampleRequest req) {
        service.save(BeanUtil.copyProperties(req, DemoExample.class));
        return R.success();
    }

    @SLog(title = "修改示例")
    @PutMapping("/update")
    @DistributedLock(key = "'demo:example:' + #req.id", expireTime = 10000)
    @SaCheckPermission(orRole = BaseConstant.ROLE_SUPER_ADMIN, value = "demo:example:update")
    @Operation(summary = "修改")
    public R update(@RequestBody @Valid DemoExampleRequest req) {
        service.updateById(BeanUtil.copyProperties(req, DemoExample.class));
        return R.success();
    }

    @SLog(title = "删除示例")
    @DeleteMapping("/{id}")
    @SaCheckPermission(orRole = BaseConstant.ROLE_SUPER_ADMIN, value = "demo:example:delete")
    @Operation(summary = "删除")
    public R delete(@PathVariable("id") Long id) {
        service.removeById(id);
        return R.success();
    }
}
```

> 写操作入参与查询入参均为 `domain/dto` 下的 DTO（见 §10），Controller 不直接接收 `Entity`。

## 10. DTO / VO / Query 分层约定

复杂表单禁止直接把 `Entity` 作为入参/出参，按职责拆分：

| 类型 | 命名 | 位置 | 用途 |
|------|------|------|------|
| 新增/修改入参 | `{Entity}Request` | `domain/dto` | 创建/更新请求体 |
| 查询入参 | `{Entity}QueryRequest` | `domain/dto` | 分页/列表查询参数 |
| 响应体 | `{Entity}VO` / `{Entity}Response` | `domain/vo` | 出参，隐藏内部字段/脱敏 |

约定：
- 新增与修改若字段差异小可共用 `Request`，差异大则拆 `SaveRequest` / `UpdateRequest`
- 出参永远不入 `Entity`，即使字段完全相同（避免后期泄露内部字段）
- Entity ↔ DTO 转换用 `BeanUtil.copyProperties` / `MapStruct`（同模块统一一种），禁止手写大量 getter/setter
- ⚠️ 实体上的**非表字段**（如 `menuIds`）不要声明 `transient`——Hutool `BeanUtil.copyProperties` 会跳过 `transient` 导致字段静默丢失（曾致角色-菜单绑定失效）；用 `@TableField(exist = false)` 声明
- Volatile 基类字段（如 `is_deleted`）若非业务需要，用 `@IgnoreBaseField` 忽略
- 密码/token 等敏感字段不出现在 VO，如需脱敏用 `@SensitiveMask`

查询入参示例（配合 `PageReq`）：

```java
@Data
@EqualsAndHashCode(callSuper = true)
public class OrderQueryRequest extends PageReq<Order> {
    @Schema(description = "订单号")
    private String orderNo;
    @Schema(description = "状态")
    private Integer status;
}
```

## 11. 异常与错误码规范

- 统一异常继承体系：`BusinessException`（业务异常，`R.error(msg)` 返回）
- 框架级已定义 `FrameworkErrorCode`（HTTP 错误映射 + 通用 200/400/500），对应 `R` 的 `code`
- **common 内**认证/会话错误：`AuthErrorCode`（如 `LOGIN_EXPIRED=1003`，`LoginUtil` 所在模块不得反向依赖 system）
- 业务模块如需专用错误码，仅自定义 `IErrorCode` 实现，**code 段需全局唯一**，避免与框架码冲突：

| 段位 | 归属 |
|------|------|
| `1xx/2xx/4xx/5xx` | HTTP 标准/通用（FrameworkErrorCode，如 `PARAM_ERROR=400`/`SYSTEM_ERROR=500`） |
| `900xxx` | 框架级 http 客户端错误（FrameworkErrorCode） |
| `1000`–`1002`/`1004`… | system 业务（`SystemErrorCode`：密码/用户/锁定…） |
| `1003` | common 认证（`AuthErrorCode.LOGIN_EXPIRED`，见上） |
| `401` | common 认证（`AuthErrorCode.NOT_LOGIN=401`「请先登录」） |
| `1404`/`1405` | 开放 API 加解密/签名（`ApiErrorCode`：RSA 解密失败/签名校验失败） |
| `10xxxx`+ | 业务模块自用（各模块预注册段位，禁止撞车） |

- **新增码必须登记**到对应 `IErrorCode` 枚举（及本表），禁止在业务代码写魔法数字
- **业务层一律用枚举取码**，不写裸数字：`R.error(AuthErrorCode.FORBIDDEN.getCode(), "…")` / `R.error(FrameworkErrorCode.PARAM_ERROR.getCode(), "…")` / `throw new BusinessException(FrameworkErrorCode.SYSTEM_ERROR.getCode(), "…")`。枚举只做**数值载体**，改枚举不改数值 ⇒ 客户端契约不变
- **例外：框架映射层的裸 HTTP 码保留**——`GlobalExceptionConfig` / `SaTokenExceptionConfig` 里直接写的 `403` / `400` 是**客户端可见的 HTTP 状态契约**（前端 `request.ts` 按状态码分流），改成枚举取值一旦枚举调整就会静默改变 HTTP 状态。业务层用枚举、映射层用字面量，是刻意分工，不是漏改
- 校验/错误提示抛 `org.jetbrains.annotations` 无关的普通 `BusinessException`
- 全局异常由 `jffast-starter-web` 统一捕获转为 `R`，Controller 内禁止 try-catch 后吞掉异常重包一层，除非需要补充上下文

```java
if (order.getAmount().compareTo(BigDecimal.ZERO) <= 0) {
    throw new BusinessException("订单金额必须大于 0");
}
```

## 12. 参数校验规范

- 入参校验用 Jakarta Bean Validation：`@Valid` + `@NotBlank`/`@NotNull`/`@Size`/`@Min` 等，禁止在方法内手写 if 抛异常（业务规则除外）
- DTO 字段上注解，Controller 入参用 `@Valid`；分组校验（新增/修改必填差异）用 `groups`
- 简单 `@RequestParam` 分页/ID 参数直接用字段类型约束（非业务规则不额外校验）
- 跨字段/依赖数据库的业务校验放在 Service，抛 `BusinessException`

```java
@PostMapping("/create")
public R create(@RequestBody @Valid OrderRequest req) { ... }
```

```java
public class OrderRequest {
    @NotBlank(message = "订单号不能为空")
    private String orderNo;
    @NotNull(message = "金额不能为空")
    @DecimalMin(value = "0.01", message = "金额必须大于 0")
    private BigDecimal amount;
}
```

## 13. 权限与角色规范

- **超级管理员**（`role_key = super_admin`，`role_id = 1`）通过 `@SaCheckPermission(orRole = BaseConstant.ROLE_SUPER_ADMIN)` 自动拥有所有权限，**无需**在 `sys_role_menu` 表配置菜单关联
- 新增菜单/按钮：在**该模块自己的** SQL 里添加 `sys_menu` INSERT（系统模块 → `system_init_data.sql`；示例模块 → `demo_init_data.sql`），超级管理员自动获得权限
- ⚠️ **菜单主键必须全局唯一（跨文件）**：可选模块脚本（`sys_post.sql` / `sys_task.sql` / `sys_file.sql` 等）用 `INSERT IGNORE` 以保证幂等，撞号时**后导入的一方整行被静默丢弃**——表现是「菜单永远不出现，导入也不报错」。段位现状：`1000-1011` + `11xx~20xx`、`2310/2311` 属 `system_init_data.sql`；`1012/1013/1014` + `21xx/22xx/23xx` 属岗位/异步任务/文件三模块；`1015-1017` + `24xx-26xx` 属监控/缓存/OAuth2 接入；`200-223` 属示例模块；`3000+` 属工作流；`9000+` 属 AI。新菜单请**顺延取未用段位**，并由 `MenuSeedIdUniquenessTest`（`jffast-boot` 测试）在 `mvn test` 阶段拦截重复
- 普通角色需通过 `sys_role_menu` 手动分配
- 权限标识格式：`模块:业务:操作`（如 `system:job:add`、`demo:product:view`）
- 业务接口必须显式声明 `@SaCheckPermission`，禁止裸接口（或明确标记匿名放行）

### 13.1 角色 / 用户写路径（授权一致性）

- **角色新增用 `createRole`、更新用 `updateRole`**（服务层不存在 `saveRole`）；有效 `roleKey` 与 `dataScope` 由 Controller 一次计算并写回实体，Service 不提供默认值，缺失即失败（fail-closed）
- **集合字段 null / `[]` 语义**：`roleList` / `deptList` / `menuIds` / `deptIds` 统一为 **null = 不修改、`[]` = 清空、非空 = 整体替换**；`dataScope != 5` 时清空 `sys_role_dept` 绑定；`syncMenus=true` 且 `menuIds=null` 属防御分支，保持原绑定并告警，不得当成清空
- **`sys_user.role_id` 是 `sys_user_role` 的冗余缓存**：以 `sys_user_role` 为权威；`roleList != null` 时必须显式写 `role_id`（`[]` 写空串），不能依赖全局 `insert-strategy/update-strategy: NOT_EMPTY`；`roleList=null` 的创建保持 NULL、更新保持原值，读取侧 NULL 与 `''` 等价
- **`sys_role.is_open` 只控制菜单树是否展开，不参与授权**；权限变更走 `menuIds` / `dataScope`
- **非空 `dept_id` 必须存在**；无部门请传 `null` 或不传（不再接受 `0`）
- **更新目标不存在一律返回「角色不存在 / 用户不存在」**，先校验后写入，不得部分写入
- 非超管写角色 / 分配角色受「秩 + 菜单子集 + 自身角色不可变」约束：非超管不得创建 `dataScope=1/5`、不得授予自己没有的菜单、不得修改自己所属角色；操作者角色缺 `roleKey` / `dataScope` 时按「操作者数据范围异常」拒绝
- 删除角色前双表并查绑定（`sys_user_role` + `sys_user.role_id`），任一存在即拒绝

### 13.2 数据权限边界

- `@DataPermission` **只在标注的方法上生效**（注解驱动，无全局行级过滤）；未标注的方法按全量访问，新增查询接口时须显式判断是否需要数据权限
- 异步任务必须在**提交线程**用 `DataPermissionSqlBuilder.resolve(...)` 取得注解元数据并快照 SQL，执行线程恢复、`finally` 还原（`SysTaskContext`）
- 数据权限是**快照语义**：任务执行期间角色变化不影响已提交任务；高风险操作请缩短任务时长或分批
- 数据范围 SQL 由 `DataPermissionSqlBuilder` 生成（字段名 / ID 白名单清洗），禁止把外部输入直接拼进 SQL；注解缺失或解析失败时 fail-closed

## 14. Starter 开发规范

- 每个 Starter 必须有 `XxxAutoConfiguration` 类，使用 `@AutoConfiguration`
- 在 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册
- 使用 `@ConditionalOnProperty` 控制功能开关，前缀统一 `jffast.xxx`
- **Bean 注册**：Starter 内 Bean 统一通过 `@Bean` 方法注册，**禁止** `@Component`/`@Service`/`@Repository`（避免组件扫描与 `@Bean` 双重注册冲突）
- **条件注解一致性**：Controller 和 Service 都必须加 `@ConditionalOnProperty`，确保开关关闭时整个模块不注册
- **`@MapperScan` 独立配置**：必须放在独立 `@AutoConfiguration` 类，不能与 `MybatisPlusInterceptor` 等 Bean 定义同配置类（否则 `sqlSessionFactory` 循环依赖）
- **Mapper 延迟注入**：`@Bean` 方法/构造器注入 Mapper 时加 `@Lazy`，打破 `sqlSessionFactory` ↔ Mapper 循环依赖
- **多实现 `@Primary`**：接口多实现时，增强实现标 `@Primary`，基础实现用 `@ConditionalOnMissingBean`

## 15. 发送、事务与缓存规范（并发/事务/Redis）

- `@Transactional(rollbackFor = Exception.class)` 只加在跨表/跨实体强一致方法；单表操作用基类事务即可
- **避免长事务**：事务内禁止做远程调用/循环查库大集合/等待锁；只读查询不加事务
- **外部副作用放事务提交后**：WebSocket 推送、邮件 / 短信等外部渠道调用统一在 `afterCommit` 回调里执行，避免外部超时拖长事务、回滚后消息已发出
- 分布式场景用 `@DistributedLock`（Redis SETNX）保护写操作，配合 `@RateLimit` 限流
- Redis key 统一前缀，格式 `{业务}:{对象}:{标识}`（如 `order:detail:{id}`），全局常量见 `BaseConstant` 缓存前缀；
- 缓存写操作注意一致性与过期时间；敏感数据不落缓存（或脱敏后落）
- **权限类缓存必须可失效**：权限 / 菜单缓存一律带 TTL，且所有会改变权限的写操作（角色-菜单绑定、菜单权限、用户角色）在同一入口失效对应 key；不要新增无 TTL 的权限哈希，避免权限永久停留在旧值
- **授权变更的会话失效**：角色授权字段（`roleKey` / `dataScope` / `dataScope=5` 的部门绑定集合）或用户角色 / 部门变化后，在事务内发布 `RoleAuthorizationChangedEvent` / `UserAuthorizationChangedEvent`，由 `@TransactionalEventListener(phase = AFTER_COMMIT, fallbackExecution = false)` **同步**撤销会话——禁止 `@Async`（否则请求返回后旧会话仍可用），事务回滚不执行。角色**创建**路径不发布事件、不踢人；仅 `menuIds` 变化走权限缓存失效，不踢人

## 16. 可观测性与安全

### Actuator / Metrics / Tracing / Logging

- 统一由 `jffast-starter-web` 通过 `application-web-actuator.yml`、`application-web-tracing.yml`、`application-web-logging.yml` 自动下发，业务模块无需重复配置
- **暴露策略分层**：默认与生产仅暴露 `health`、`info`；`dev` 环境额外暴露 `metrics`、`prometheus`。需要更多端点时在环境 profile 里显式覆盖 `management.endpoints.web.exposure.include`，不要改默认值
- `/actuator/health/**` 通过 `jffast.security.auth-excludes` 放行（任何环境），其余 actuator 端点仍受登录与权限校验
- TraceId/SpanId 自动注入 MDC，日志格式：`[${spring.application.name},${traceId},${spanId}]`
- `TraceIdFilter` 优先复用 Micrometer Tracing 的 traceId/spanId；链路未开启时降级 ULID，并回写 `X-Trace-Id`/`X-Span-Id`
- Zipkin 上报：`management.zipkin.tracing.endpoint=${ZIPKIN_ENDPOINT:http://localhost:9411/api/v2/spans}`

### 敏感字段脱敏

- 字段级脱敏：`@SensitiveMask(type = SensitiveMask.MaskType.MIDDLE_MASK, prefixKeep = 3, suffixKeep = 4)`
- Jackson 序列化内置 `SensitiveMaskSerializer`，DTO 注解字段自动脱敏
- Excel 导出内置 `SensitiveMaskCellWriteHandler`，注解字段自动脱敏
- 日志脱敏：`logback-spring.xml` 引入 `<include resource="logback-jffast.xml"/>` 启用 `SensitiveMaskMessageConverter`
- 运行时工具：`SensitiveMaskUtil.mask(Object)` / `maskText(String)` / `mask(String, MaskType)`

### XSS 处理

- `XssUtil.clean` 仅对 `< > &` 做 HTML 实体转义，不过度转义 `" ' ( )`
- XSS 过滤覆盖 form/query/header 参数与 **JSON 请求体**（`jffast.web.xss.json-clean`，默认开启，含 `\uXXXX` 转义绕过写法）；携带代码/模板的字段经 `jffast.web.xss.json-skip-fields` 豁免（默认 `bpmnXml`、`contentTemplate`），非法 JSON 原样放行、由消息转换器报 400
- JSON 安全渲染仍由前端负责（Vue 模板默认转义）；服务端确需额外清洗时，对 DTO 字段加自定义 Jackson 反序列化器并调用 `XssUtil.clean`（`@SensitiveMask` 只做脱敏、不做 XSS 清洗，勿混用）

### 弱口令 / 默认口令（dev / test）

- `jffast.system.init-password` 的默认值 `test1234` 是**随仓库公开的统一测试填充值**，目的是让新人 clone 后零配置登录。本机开发**不算缺陷**；真正的缺陷是它被搬到了**远程端点**上
- 因此 `DevProfileGuard` 有一条硬拦截（启动期）：**仍用默认口令，且数据源 / Redis 指向非本机地址** ⇒ 直接拒绝启动，并打印三条可操作的处理方式（注入强口令 / 置空改随机生成 / 把 host 指回 127.0.0.1）
- `demo` profile 是显式对外展示形态（写操作短路），只打 ERROR 级告警、不阻断启动 —— 拦了等于废掉演示能力
- `prod` profile 的 `init-password` 无默认值（`${JFFAST_INIT_PASSWORD}`），缺失即启动失败；容器形态另有 `Dockerfile` 的 ENTRYPOINT 硬把关
- 判据集中在 `DevProfileGuard.collectWeakCredentialFindings(...)`（纯函数，可单测）；**新增"默认口令 + 远程端点"这类组合时改那一处**，不要在各处散写判断

### 回跳地址 / 跳转目标（开放重定向）

- 任何由客户端传入、最终被回显或用于跳转的地址（OAuth2 `targetUri`、登录后跳转 `redirect` 等）必须过**白名单**：只放行站内相对路径（单个 `/` 开头），拒绝绝对 URL、协议相对 URL（`//`）、`..`、反斜杠、控制字符
- **签名不等于校验**：`state` 签名防的是"被篡改"，防不了"一开始就填了别人的地址"——服务端替攻击者签一个 `https://evil.com` 再原样回显，同样是开放重定向。白名单必须在**入参侧**落地，出参侧再过一次
- 控制字符检查必须**先于** `trim()`：`String.trim()` 会吃掉首尾的 `\0` `\n` `\r`（都 ≤ U+0020），先 trim 再检查会让 `"/path\0"` 变成合法值而绕过白名单

切换存储只改 `type`，业务代码不变；切换会让存量文件 URL 形态不一致，迁移需自行搬运。

- 上传统一先过 `FileUploadValidator`（`jffast.file.storage.max-size` + `allowed-types`），各存储实现不得绕过；对象名由存储实现生成，业务代码只持有访问 URL
- 删除顺序固定为「先删存储对象、再删 `sys_file` 记录」：存储失败时保留记录可重试，避免产生无记录的孤儿对象

- 同步接口适合小数据量（≤1 万行）；大数据量走异步（内置上限 10 万行）
- 导入密码类字段按初始化密码生成（如用户导入），导入结果必须回显失败行与原因
- **逐行校验必须覆盖所有 NOT NULL 列**：用户导入的 `real_name`（姓名）是 `NOT NULL` 列，缺姓名若不拦，insert 会触发 NOT NULL 违例把整批 `saveBatch` 回滚——一个空单元格废掉整个文件，且失败明细里看不到是哪一行的问题。规则：**入库前的每一列都要在应用层先校验并给出可读文案**（如「第 N 行：姓名不能为空」），坏行只跳过该行、不影响同批其他行；字段长度也要按列宽校验（如姓名 ≤ 20）
- **异步上下文**：在**提交线程**快照操作者与数据权限 SQL（`SysTaskContext`），任务线程恢复上下文、结束后还原；队列满触发 `CallerRunsPolicy` 时同样保证调用线程上下文不被污染
- **任务线程池**：固定 2 线程，队列容量 `jffast.system.task.queue-capacity`（默认 `100`，必须 `> 0`，`<= 0` 启动失败）

| 分页查询 | `/sys/post/page` | GET | `system:post:view` |
| 详情 | `/sys/post/detail/{id}` | GET | `system:post:view` |

- 岗位编码 `post_code` 全局唯一，保存前做重复校验

### 19.3 异步任务接口（内置，`sys_task`）

| 操作 | 路径 | HTTP 方法 | 权限标识 |
|------|------|----------|---------|
| 分页查询 | `/sys/task/page` | GET | `system:task:view` |
| 详情 | `/sys/task/detail/{id}` | GET | `system:task:view` |
| 下载结果文件 | `/sys/task/download/{id}` | GET | `system:task:download` |
| 删除 | `/sys/task/delete/{id}` | DELETE | `system:task:delete` |

- 表 `sys_task`（脚本 `sql/sys_task.sql`，含菜单种子，幂等可重复执行）
- 关键字段：`task_type`（export/import）、`biz_type`（如 user）、`status`（0待处理/1进行中/2已完成/3失败）、`progress`、`total_rows`/`success_rows`/`fail_rows`/`fail_detail`、`file_path`/`file_name`、`error_msg`
- 结果文件落盘 `jffast.file.storage.local.path` 下 `task/` 子目录；删除任务时一并清理文件
- **归属隔离**：分页 / 详情 / 下载 / 删除均按 `create_by` 隔离——超管全量，普通用户仅本人任务；下载路径必须位于任务目录内（防 DB 篡改导致任意文件读取）；历史 `create_by=0` 任务归超管
- **部署形态**：任务文件是本地磁盘文件，多实例部署需把存储目录挂共享卷（本地目录不跨实例），否则在非落盘实例上下载会 404

## 20. 分页约定

- 请求参数名：`pageNo` 和 `pageSize`（直接入参或继承 `PageReq`）
- 响应格式：`{ code: 200, data: { total: 100, pages: 10, list: [...] } }`（`PageRes`）

## 21. 数据库 / SQL 规范

- 字段命名 `snake_case`；表必须有 `id`，建议含 `create_by/create_time/update_by/update_time`（由 `BaseEntity` 自动填充）；`is_deleted` 仅在启用逻辑删除（`@TableLogic`）时才建，不要留没人写的死列
- 主键统一 `id BIGINT`（`IdType.ASSIGN_ID`）；金额用 `DECIMAL`，时间用 `DATETIME`，状态/开关用 `TINYINT`
- 索引命名：主键 `pk_`，唯一 `uk_{字段}`，普通 `idx_{字段}`；禁止给低基数列盲目加普通索引导致冗余
- 多表关联尽量在应用层完成，少用 JOIN；外键逻辑约束，不用数据库外键（已有约束策略除外）
- 复杂查询写 XML Mapper，简单 CRUD 用 LambdaQueryWrapper；XML 与 `sql/` 脚本用 UTF-8 无 BOM
- `sql/` 目录为 schema 基线脚本；结构变更需同步更新对应基线脚本（或提供增量脚本并登记版本），不直接改生产库
- **多租户兼容（Base 默认单租户）**：新增业务表建议预留 `tenant_id BIGINT NOT NULL DEFAULT 0` 与 `idx_tenant_id`；现有 `sys_config` / `sys_notification_record` / `sys_oauth2_client_config` / `sys_user` 的唯一键暂未包含 `tenant_id`，下游启用多租户时须自行调整唯一键（附迁移 / 回滚脚本）

## 22. 后端测试规范

- 单元测试用 JUnit 5；纯逻辑（工具类/枚举/规则）必须覆盖边界值
- 涉及 Spring 上下文的用 `@SpringBootTest`，数据访问层可用 `@MybatisPlusTest`/`@DataJpaTest` 或 H2 内存库隔离
- Controller/Service 用 MockMvc / Mockito 测正反路径（成功 + 参数错误 + 异常）
- 异常路径必须验证：`BusinessException` 转 `R.error` 后的 `code/msg`
- 覆盖率：核心模块新增/修改代码行覆盖率 ≥ 80%；用 Codecov 聚合各模块 Jacoco 报告
- 测试数据不污染生产：测试用独立库/事务回滚
- 命名：`XxxServiceTest` / `XxxControllerTest`；方法 `testXxx_shouldXxx_whenXxx`

## 23. 新功能开发流程（推荐）

**核心原则：代码生成器打底 + 业务定制。**

1. **建表**：按 §21 规范建表
2. **生成基础代码**：系统管理 → 开发工具 → 代码生成器，选表/包/生成类型（`crud`/`tree`/`masterDetail`），保存到本地
3. **注册模块**：`jffast-biz/pom.xml` 加 module、`jffast-bom/pom.xml` 加依赖管理、`jffast-boot/pom.xml` 加依赖；前端 `src/router/modules/` 加路由
4. **业务定制**：在生成基础上改字段校验、关联查询、按钮权限、特殊交互
5. **验证**：编译通过、接口文档展示、前端 CRUD 正常、操作日志记录、关键用例有测试
6. **文档同步**：更新功能文档与 README

**为什么不用 AI 直接生成整个模块？** 生成器已固化项目约定（包名/路径/注解/分页/权限/前端三件套），避免每个新模块风格不一致。先用生成器跑通基础 CRUD，再聚焦业务差异。

## 24. 代码生成器使用规范

**入口（三选一，推荐 CLI）**：

1. **命令行（不启动应用，AI / 新人首选）**——在工程根目录运行：

   ```bash
   mvn -q -pl jffast-common -am compile exec:java \
     -Dexec.mainClass=cn.jfspeed.common.core.util.CodeGeneratorCLI \
     -Dexec.args="--url=jdbc:mysql://127.0.0.1:3306/jffast --user=root --password=xxx \
                  --table=sys_xxx --package=yyy --author=zhang"
   # 树表：--gen-type=tree --parent-field=parent_id --name-field=name
   # 主子表：--gen-type=masterDetail --child-table=... --child-fk=...
   ```

2. **页面**：系统管理 → 开发工具 → 代码生成器（后端接口 `/sys/codegen/*`）
3. **JAR / 容器部署**：`POST /sys/codegen/download-zip` 打包下载（`save-local` 在 JAR 下被拒绝）

**生成类型**：

| 类型 | 适用场景 | 关键参数 |
|------|---------|---------|
| `crud` | 单表增删改查 | 表名、包名、模块名 |
| `tree` | 树形结构（菜单/部门/分类） | 表名、包名、`parentField`（默认自动检测 `parent_id`/`pid`）、`nameField` |
| `masterDetail` | 主从表（订单+明细） | 主表、子表名、`childForeignKey`、`childPackageName` |

**生成文件清单**：

| 分类 | 文件 | 说明 |
|------|------|------|
| 后端 | `entity/{ClassName}.java` | 继承 `BaseEntity` |
| 后端 | `mapper/{ClassName}Mapper.java` | MyBatis-Plus Mapper |
| 后端 | `service/{ClassName}Service.java` | 继承 `BaseService`，含 `page()` |
| 后端 | `controller/{ClassName}Controller.java` | 继承 `BaseController`，含 5 个标准接口，每个接口带 `@SaCheckPermission`（权限标识 `{module}:{pageName}:{view\|add\|update\|delete}`，并放行 `super_admin`） |
| 后端 | `domain/dto/{ClassName}Request.java` | 新增/修改 DTO（**始终生成**，含 `id` 字段；Controller 依赖它） |
| 后端 | `domain/dto/{ClassName}QueryRequest.java` | 查询 DTO（`includeDto=true` 时） |
| 后端 | SQL 脚本 | 自动生成菜单 SQL（C 类型菜单 + `view`/`add`/`update`/`delete` 四个 F 按钮，权限标识与 Controller 一致） |
| 前端 | `src/api/{module}.js` | `createCrud` 工厂 API |
| 前端 | `src/pages/{module}/{pageName}/index.vue` | 列表页 |
| 前端 | `src/pages/{module}/{pageName}/save.vue` | 表单弹窗 |
| 前端 | `src/router/modules/{module}.ts` | 路由配置片段 |

**参数约定**：`packageName`（如 `order` → `cn.jfspeed.order`）、`moduleName`（前端模块名）、`author`（默认 `jffast`）、`includeDto`（复杂表单建议开启）

**限制**：仅本地开发模式支持"保存到本地"，JAR 模式只能预览/下载；生成后必须手动注册到 `jffast-biz`、`jffast-bom`、`jffast-boot` 及前端路由。
